# ODoutreach — walking every screen as a client would, 26 August 2026

Done in Chrome against the live site `https://opensdoors.bidlow.co.uk`, signed in as
`greg@bidlow.co.uk`, the same way Greg will open it in front of the OpensDoors owner.

**Why a human did this and not the relay.** The relay runs Claude Code headless with
`--allowedTools "Write,Edit,Read,Glob,Grep,Bash"`. It has no browser. Queue item 16 says
"Use Chrome, signed in, and actually click through it" — which the relay physically cannot
do. So it was done here instead, and the findings were handed back to the relay as items
26, 27 and 28.

Every timing below is `performance.getEntriesByType('navigation')[0]` — real measurement,
not impression. "TTFB" is time to first byte, "Load" is `loadEventEnd`.

---

## 1. What a client would notice, worst first

### 1. The automatic related-domain detection does not exist as far as anyone can see

This is the thing Greg said mattered most, in his own words:

> "when you have a bt.com, bteurope.com etc. there must be no human entering the domain or
> email addresses manually, it must be automated, the owner is willing to take a small risk
> on possible prospects being missed as this must be an automated task and human error is
> the single thing causing do not contact emails to be contacted."

The Do-not-contact screen currently says the opposite, twice:

> "Some companies use more than one domain. Blocking bt.com does not block bteurope.com on
> its own — **nothing can tell they are the same company without being told.** List them
> here..."

> "No related companies listed yet. **Add one when a client blocks a company that uses more
> than one domain**..."

And underneath it is a **manual two-box form**: Company, Their domain, Add domain. It even
uses BT as the example — the exact example Greg gave.

The machinery to do it automatically is all there:

| What exists | Where |
|---|---|
| `discoverLinksForClient`, `planClientFamilyProposals`, `persistProposalPlans` | `src/server/suppression/family-discovery-run.ts` |
| `listPendingFamilyProposals`, `confirmFamilyProposal`, `rejectFamilyProposal` | `src/server/suppression/family-proposals.ts` |
| Four test files | `family-discovery-run.test.ts`, `family-proposals.test.ts`, `family-proposal-schema.test.ts`, `family-proposal-tombstone.integration.test.ts` |
| A migration, already applied to the production database | `prisma/migrations/20260824180000_suppressed_domain_family_proposals` |

And none of it is reachable:

- Nothing outside that file imports `family-discovery-run`. It has no caller.
- No GitHub workflow mentions it. Nothing runs it on a schedule.
- The Do-not-contact page imports `DomainFamilyPanel` and `listDomainFamiliesForClient` —
  the **manual** families. It does not import `listPendingFamilyProposals`.
- `do-not-contact-actions.ts` has only `addToDoNotContactAction`, `addDomainToFamilyAction`
  and `removeDomainFromFamilyAction`. There is no confirm or reject action.

So the proposals table can never be written to, the panel can never show anything, and the
manual form is the only route. **Built, migrated, tested, and it has never once fired.**
That is the seventh instance of the defect this project keeps producing, and it landed on
the highest-stakes feature in the product.

Queued as **item 26**.

### 2. `Campaigns` reads 0 for all 17 clients

The Clients list — the front door — has a Campaigns column, and every row says 0. Including
OpensDoors with 647 contacts, and Train Hugger with 743 sends. Meanwhile Reports says 1,212
emails have been sent.

It is `_count.campaigns` in `src/server/queries/clients.ts`. Nothing writes Campaign rows;
sends hang off sequences. So the column counts a table nobody uses, and the first screen of
the demo says every client has done nothing.

### 3. The install banner covers live data, and comes back after every restart

`position: fixed; inset-x-0; bottom-0; z-50`, centred over the bottom of every page. On
Reports it sits on top of the client-name column of the per-client table, hiding rows.

It *is* dismissible — the button carries `aria-label="Dismiss install prompt"` and works —
but the flag is written to **`sessionStorage`** as `odoutreach:pwa-install-dismissed`. A new
tab brings it back. A browser restart brings it back. Which is exactly the state Greg's
machine will be in tomorrow morning.

### 5. The same thing, shown two and three times

- **Client workspace**: the tab bar, the numbered "Workflow" pills, and the Launch-readiness
  rows are the *same seven destinations*, stacked on one screen. Greg asked for this already:
  *"this needs to be consolidated into one tab list? i need the UI clean."*
- **Activity**: five KPI cards (EMAILS SENT / REPLIES / BOUNCES / UNSUBSCRIBES / FAILED
  SENDS), then immediately below, "Outreach metrics" repeating the same five numbers in
  different words (Total sent / Replies / Bounces / **Opt-outs** / Failed).
- **Mailboxes**: the five mailboxes are listed once in the mailbox table and again under
  Sender signatures — with the same 60-word help paragraph repeated verbatim on all four
  connected rows.
- **Outreach**: the SEQUENCE and LIST columns print the identical string on most rows.
- **Every page**: the logo appears twice, once in the sidebar and once centred in the header.

### 6. Mailboxes buries the mailboxes

Before you reach the actual list you scroll past: a "what happens when you connect" explainer,
a Microsoft admin-approval troubleshooting card containing a raw OAuth consent URL, a full
SPF/DKIM/DMARC instruction block, and a send-a-test-email form. Four screens of documentation
before the thing the page is named after.

The content is good — genuinely good, the plain-English explanations are some of the best
writing in the app. It is in the wrong order.

Also visible there: `joe@opensdoors.co.uk` shows **Connection failed** on the client being
demoed.

### 7. "Showing 200 of 200" while silently truncating

/suppression renders 868 table rows and 756 KB of HTML in one page, and says "Showing 200 of
200" for both lists. Panda Recycling alone has 30,229 blocked addresses. The domain list
starts at `songa.co.uk` — an arbitrary alphabetical window, not the first 200. The count is
not just incomplete, it claims to be complete.

### 8. Words a non-technical owner will stop on

- **"Send proof missing: 204"** in red on the front page. 17% of all sends.
- **"Not reached: 252 (failed + bounces + suppressed + proof missing)"** — a formula.
- **"Delivered — Not tracked"** rendered as a large headline metric. It reads as broken.
- **"Admin diagnostics"**, **"Connection diagnostics (owner only)"** on client screens.
- **BidlowAI: reply rate 133.3%** (3 sent, 4 replies).
- **Idverde: 4 sent, 20 "not reached", 20 "proof missing"** — sends and contacts counted in
  the same table, so the numbers look impossible.

## 2. Two failing do-not-contact syncs — a safety finding, not a UI one

On /suppression, live, right now:

- **Train Hugger — Whole domains — "Last sync failed"**, serving 373 stale rows. Train Hugger
  is the biggest sender in the system, 743 emails.
- **Pareto FM — Whole domains — "Last sync failed"**, 0 rows. Pareto FM currently has **no
  domain blocklist at all**.

A blocklist that silently stopped updating is precisely how a do-not-contact address gets
contacted. Queued as **item 28**.

## 3. What is genuinely good, and should be shown off

Worth saying, because the list above is one-sided:

- The Do-not-contact copy explains itself in plain English, and the sheet sync is live —
  OpensDoors resynced at 14:13 and 14:14 today, 13 addresses and 59 domains.
- The verification-send form is properly guarded: one named mailbox, a fixed recipient list,
  a typed confirmation, and it says out loud that it consumes a daily slot.
- Mailboxes explains what connecting does *before* you click, and explains why a second
  signature would appear and whose fault it would be.
- Activity is honest about what it does not know: *"'Sent from mailbox' means ODoutreach
  handed the email to the connected mailbox. It does not guarantee inbox placement."*
- Launch readiness on the client overview is a good screen. It says "Reduced capacity — 4
  connected · 120/day capacity" rather than a green tick.

The instinct to be honest on screen is the best thing in this product. The problem is that
the honesty is written in the vocabulary of the people who built it.
